Pubgrade 0.3.1 runs on FOCA 0.23.0, lets its Helm chart request
certificates from a namespaced cert-manager Issuer, and notifies Pubgrade of
its own releases, so that subscribed deployments, Pubgrade's own among them,
follow them. The API (2.2.0) and the chart's values stay compatible; it
works with Pubgrade-Sidecar 0.3.0. Until 1.0.0, releases are pre-releases.
Read [Upgrading to FOCA
0.23](https://pubgrade.readthedocs.io/en/v0.3.1/deployment/#upgrading-to-foca-023)
before upgrading, and see [Ingress and
certificates](https://pubgrade.readthedocs.io/en/v0.3.1/deployment/#ingress-and-certificates)
for the Issuer kind.

## Breaking changes

- FOCA 0.23.0 (from 0.22): build types with a trailing newline (e.g.,
  `"production\n"`) get a 400 with the code `pattern-mismatch` instead of
  being accepted, and a configuration of your own
  (`pubgrade.configSecret`) without `server.max_content_length` limits
  request bodies to 10 MiB (before: no limit); the image's configuration
  keeps its 1 MiB, and the upgrade notes show how to find stored build types
  with a trailing newline (#142, #141)

## Features

- Chart: `pubgrade.ingress.https.issuerKind` selects a namespaced
  cert-manager `Issuer` instead of a `ClusterIssuer` (the default), and
  `pubgrade.ingress.annotations` override the chart's issuer annotation, or
  remove it with `null`; an unknown kind, an empty issuer with HTTPS on and
  annotations that name both kinds fail the rendering (#136, #138)
- The release workflow notifies Pubgrade of the released app image
  (`elixircloud/pubgrade:X.Y.Z`) in a job `Notify Pubgrade`, if the
  repository sets `PUBGRADE_URL`, so that subscribed deployments follow the
  release (#139)
