Pubgrade 0.3.1 runs on FOCA 0.23.0 and lets its Helm chart request
certificates from a namespaced cert-manager Issuer. Its release workflow can now
notify Pubgrade of each release (if `PUBGRADE_URL` is set), so that
subscribed deployments follow it. The API stays at 2.2.0, the chart's existing
values keep their meaning, and it works with Pubgrade-Sidecar 0.3.0. Until
1.0.0, releases are pre-releases. Read [Upgrading to FOCA
0.23](https://pubgrade.readthedocs.io/en/v0.3.1/deployment/#upgrading-to-foca-023)
before upgrading, and see [Ingress and
certificates](https://pubgrade.readthedocs.io/en/v0.3.1/deployment/#ingress-and-certificates)
for the Issuer kind.

## Breaking changes

- FOCA 0.23.0 (from 0.22): build types with a trailing newline (e.g.,
  `"production\n"`) get a 400 with the code `pattern-mismatch` instead of
  being accepted, and a configuration of your own
  (`pubgrade.configSecret`) without `server.max_content_length` limits
  request bodies to 10 MiB (before: no limit); the image's configuration
  keeps its 1 MiB, and the upgrade notes show how to find stored build types
  with a trailing newline (#142, #141)

## Features

- Chart: `pubgrade.ingress.https.issuerKind` selects a namespaced
  cert-manager `Issuer` instead of a `ClusterIssuer` (the default), and
  `pubgrade.ingress.annotations` override the chart's issuer annotation, or
  remove it with `null`; an unknown kind, an empty issuer with HTTPS on and
  annotations that name both kinds fail the rendering (#136, #138)

## Fixes

- Chart: an annotation in `pubgrade.ingress.annotations` with the same key
  as the chart's issuer annotation replaces it; up to chart 0.3.0, the key
  was rendered twice (#136, #138)

## Documentation

- The README and `CITATION.cff` cite the concept DOI of Pubgrade's releases
  on Zenodo, [10.5281/zenodo.24093877](https://doi.org/10.5281/zenodo.24093877)
  (#134, #135)

## Maintenance

- The release workflow registers the released app image
  (`elixircloud/pubgrade:X.Y.Z`) at Pubgrade in a job `Notify Pubgrade`, so
  that subscribed deployments follow the release; it is skipped unless the
  repository variable `PUBGRADE_URL` is set, and needs the secret
  `PUBGRADE_TOKEN` and an approval in the `release` environment (see
  [Versioning and
  releases](https://pubgrade.readthedocs.io/en/v0.3.1/development/#versioning-and-releases))
  (#139)
