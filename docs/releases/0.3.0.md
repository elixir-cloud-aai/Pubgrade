Pubgrade 0.3.0, released together with
[Pubgrade-Sidecar](https://github.com/elixir-cloud-aai/Pubgrade-Sidecar) 0.3.0,
adds a GitHub Action that notifies Pubgrade of a new image from a
repository's CI, so that its subscribers roll it out, and a script that
checks a deployment end to end. Its Helm chart's security contexts are now
configurable, so that it deploys on clusters that reject pods naming a
seccomp profile (e.g., CSC Rahti since November 2026). The documentation
includes that of Pubgrade-Sidecar 0.3.0. Until 1.0.0, releases are
pre-releases. Read the chart's [security
contexts](https://pubgrade.readthedocs.io/en/v0.3.0/deployment/#security-contexts)
before upgrading, and see [Notify Pubgrade from
CI](https://pubgrade.readthedocs.io/en/v0.3.0/usage/#notify-pubgrade-from-ci)
for the action.

## Features

- The composite action `actions/notify` registers a prebuilt image as a build
  of a repository from CI (`POST /repositories/{id}/builds`), and Pubgrade
  then notifies the repository's subscriptions. Reference it as
  `elixir-cloud-aai/Pubgrade/actions/notify@<commit> # v0.3.0`; it needs
  builds switched off (the default) (#88, #115)
- `tests/e2e/check.sh` checks a deployed Pubgrade end to end: it subscribes a
  test sidecar, publishes an image and checks that the Deployment rolls it
  out, then removes what it created (#113, #114)

## Fixes

- The chart's security contexts of Pubgrade, the updater and MongoDB are the
  values `podSecurityContext` and `securityContext`, with the earlier
  settings as defaults; `seccompProfile=null` removes the seccomp profile,
  e.g., for CSC Rahti. Don't upgrade from chart 0.2.0 with `--reuse-values`
  (#111, #112)

## Maintenance

- The weekly scan of the app image `latest` fails on critical and high
  vulnerabilities that have a fix, as CI and the release workflow do; the
  updater's image stays report-only (#108, #109)
- Only a new commit of a pull request cancels its CI runs in progress (#110)
- Dependabot labels all its pull requests with `type: dependencies` (#116,
  #117)
- The release workflow publishes these curated notes followed by GitHub's
  generated notes (#123)
